# File25 — V12-026 Honest Content Freshness (11 November 2026)

## Exact source and governing rule
- Parent source: `c1fceffe491ed918a5639a50a430a60316fac2ae`, an unmerged File25 PR #44 candidate. No live WordPress or DB evidence was used.
- Master Plan V12.1 V12-026: when a timestamp materially affects a user decision, show the source update date; stale or uncertain data must not be called live. Native owners supply update truth, File25 only renders it.

## One confirmed source root cause
`Future_Public_Experience::freshness()` previously accepted valid-looking ISO dates in the future as already completed updates. The Profile overview client code used `fresh.label || updated date`, permitting a source label to suppress the actual date from visible and spoken text; Timeline card updates also lacked a future timestamp check. These are three manifestations of one presentation problem: **owner-source timestamp is not reliably bound to the freshness label seen by users**.

## Bounded File25-only correction
1. Suppress future profile content-update timestamps beyond a five-minute server clock-skew allowance. Never fabricate or rewrite a File03/File21 record.
2. Make the owner-provided update date visible in a real `<time datetime>` element. Preserve any owner note as separate supplemental text rather than letting it replace the date.
3. Suppress impossible future update labels in Timeline card metadata, without modifying canonical post published/updated facts.
4. Add an actual PHP regression around `Future_Public_Experience::freshness()` for previous day, future day, small clock skew, invalid calendar date and malformed payload, plus a static checked-in JS source assertion. Do not overstate the JS assertion as a browser test.

## External blockers
Locale rendering, timezone, accessibility, native File03/21 update provenance, security/privacy, rollback and UI acceptance still require installed Staging. `Visual_Acceptance::summarize()` validates only manifest metadata: it does **not** read screenshot bytes or verify stored artifacts and cannot independently certify staging or production readiness. That assurance remains a File24/integrated release responsibility.
