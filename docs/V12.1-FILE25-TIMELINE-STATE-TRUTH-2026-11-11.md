## Root cause — status projection loses service truth
The authorized File25 `Profile_Renderer` already suppresses native Timeline queries when `timeline_search_error` is set and the Timeline service already distinguishes `provider_errors` and `truncated`. But `templates/partials/timeline.php` used a single static `spux-state--empty` for any empty item list, even after a rejected request, provider outage or bounded fetch. It also labeled empty later pages as an author with no publications, and offered no required reset/retry CTA. This is one File25 presentation root cause, not a defect in File21's publication backend.

## Five affected source scenarios and bounded correction
1. **Invalid query or disabled search:** shared error state with a safe clear-filter action, never a false no-publications message and never a substituted unrestricted search.
2. **Provider errors and zero items:** shared unavailable state with retry and explicit uncertainty; do not promise that any items were displayed.
3. **Truncated bounded retrieval and zero items:** unavailable/uncertain, not an absolute claim that no contributions exist.
4. **Valid refinements and zero matches:** shared filtered-empty state with clear-filter action; context-controlled preview remains on the same origin.
5. **Unfiltered empty page versus later pagination:** page 1 uses privacy-safe empty; an empty later page uses filtered-empty and a first-page action rather than claiming an author never published.

The change uses the already-reviewed `Components::render_state` public primitive (contract 1.3.0) and preserves native query security, existing filters, same-site URL sanitizer, localization, semantic text/icon and the existing File20/21/26 ownership. It does not introduce storage, REST writes, user roles or an unrelated backend.
