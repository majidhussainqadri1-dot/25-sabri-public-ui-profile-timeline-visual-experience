## Root causes and bounded corrections
1. **Publication/update conflation**: `timeline_meta()` mapped `updated_at ?? published_at` into a single `updated_at` field while JS always displayed “Updated”. Add separate `published_at` and `updated_at` fields, retaining the server-authoritative safe timestamp check. An update not later than the published instant is not a distinct modification. A real update takes precedence, without fabricating a new event.
2. **False provenance/verification badge behavior**: `Timeline_Service` returns `Normalized_Timeline_Item::to_public_array()`, which deliberately redacts internal `provider_id`. The previous `source_verified` check on that redacted field could never establish positive verification. The visual metadata now requires an explicit `verification_state === 'verified'` from the already-authorized public native projection, never an inferred provider ID. This is a provider-supplied status, **not** an independent File25 audit.
3. **Visual-state semantic consistency**: The shared state component already has text and icons, but all icons used the primary green text even for error/denial/warning. Explicit semantic danger/warning/success/muted icon tones restore visual correspondence, without making colour the only signal.

## Second independent source review: ambiguous canonical URLs and user clocks
- The former `new Map(timelineMeta.map(...))` silently used **last writer wins** for duplicate canonical URLs; File25 normalized native objects can legitimately share a URL while retaining distinct internal projection keys. This could attach the wrong content date or source-verification badge to a different rendered card. A pure `indexUniqueTimelineMetadata()` now excludes all ambiguous URL keys, including third repeats; it preserves unique rows, canonicalized same-origin keys and existing server-side core content. No private provider IDs or new backend are exposed.
- Because `templates/partials/timeline.php` uses `wp_date(..., new DateTimeZone('UTC'))` for publication, the client update date now also renders on the UTC calendar day rather than a visitor's uncontrolled time zone. The exact canonical absolute time remains in `<time datetime>`; localization of full native WordPress format remains a Staging acceptance concern.
- Wording `Source reports verified status` now clearly attributes the owner-provided verification flag to its source, without claiming an independent File25 identity/medical validation.
- The executable Node test now also exercises URL conflicts and UTC render-source invariants. This verifies the isolated pure JS helper, not a real DOM or screen reader.
