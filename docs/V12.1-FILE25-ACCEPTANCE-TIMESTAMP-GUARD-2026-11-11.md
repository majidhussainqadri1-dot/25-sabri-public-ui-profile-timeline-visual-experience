# File25 — V12.1 Evidence Timestamp Guard (11 November 2026)

## Source finding
- Pre-correction source SHA: `3f8fb7755021b723fbae59fbd64e8996801dc93d` (unmerged Draft PR #44).
- `Visual_Acceptance::iso_time()` verified ISO syntax/calendar/offset but did not reject `recorded_at` timestamps in the future. Therefore a future-dated screenshot record, staging record or Founder signoff could satisfy the metadata-shape validator's timestamp condition and be counted as `pass` before the event could have happened.
- This is a source-level evidence-integrity defect. It does **not** demonstrate any fraudulent evidence or a live incident.

## Root-cause correction and coverage
- Reject timestamps that are later than server now + 300 seconds (bounded clock skew) without altering historical evidence. The same helper covers surface, viewport, direction, color mode, motion mode, zoom, input, staging and Founder-signoff timestamps.
- Extend `tests/visual-acceptance.php` with actual `Visual_Acceptance::validate_evidence` regressions for future screenshot, future staging and future Founder signoff. They must fail as metadata validation, whereas valid historical exact-source fixture still passes.

## Explicit unsolved acceptance issue
`Visual_Acceptance::summarize()` checks the consistency of caller-supplied metadata; it does **not** open screenshots, hash their actual bytes, check independent reviewer credentials or prove that Staging happened. Therefore the method's `accepted` boolean **cannot** be treated as production acceptance. Cross-cutting File24 assurance, exact installed artifact checksums, real screenshots, backup/rollback, real roles/RTL/a11y, live parity and Founder acceptance remain external gates. No new File24 authority was created here.
